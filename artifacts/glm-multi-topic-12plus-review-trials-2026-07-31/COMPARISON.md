# 双模式、多主题、10+篇全文综述验证报告

## 结论先行

本轮使用智谱免费模型 `glm-4.7-flash` 完成四个真实主题试验。每个案例均建立
40条以上候选记录并解析12条全文记录。版本去重审计后，三例对应12项独立研究；
Agent评测案例的12条记录中有一组“期刊版—预印本”关联版本，对应11项独立研究。

四份正式综述均通过确定性产品质量门（章节完整、正文覆盖全部保留来源、无非法
引用、重点经验性论断均有引用或明确的综合判断标签）。独立模型审稿更严格：
“LLM幻觉范围综述”通过；其余三份仍建议研究者复核，具体问题完整保存在各案例的
`model_methodology_audit.json` 中。

## 两种模式实际呈现出的差异

### 计算机/AI技术综述

PEFT与RAG案例围绕“技术机制—实验依据—工程成本—复现性—适用边界”组织。
正文先建立方法族，再比较不同研究，而不是按论文逐篇摘要。对跨数据集、跨模型
规模和跨指标的结果明确限制直接横向比较。

适合检查：

- 技术分类是否有解释力；
- 数值和方法归因能否追溯到证据卡；
- 性能、显存、延迟、复现性和部署约束是否同时进入结论；
- 是否避免从异质实验中推出单一“最佳方法”。

### 范围综述/系统映射

幻觉与Agent评测案例围绕“领域如何定义问题—使用哪些基准与指标—覆盖了哪些
场景—证据空白在哪里”组织，不强行给出统一效果结论。结论仅适用于本次协议覆盖
的语料，不使用“系统综述”标签。

适合检查：

- 分类轴和范围映射是否完整；
- 是否把“本轮没发现”误写成“领域不存在”；
- 基准分数是否被错误解释为真实世界能力；
- 研究空白是否来自证据分布，而不是模型凭空建议。

## 建议检查顺序

每个案例按以下顺序检查：

1. `protocol.json`：研究模式、真实来源和停止条件。
2. `search_ledger.json` 与 `candidate_pool.json`：三条查询及候选规模。
3. `selection.json` 与 `included_sources.json`：筛选理由、下载成功记录和最终来源。
4. `evidence_cards.json`：逐篇全文证据、页码、局限和复现性字段。
5. `synthesis.json`：跨论文综合单元、共识、冲突与缺口。
6. `formal_review.md`：最终正式综述。
7. `product_quality.json` 与 `model_methodology_audit.json`：确定性门禁和独立审稿。

## 本轮暴露并修复的产品问题

1. arXiv客户端使用明文HTTP且没有请求超时，可能让检索长期无进度。现已改为HTTPS、
   明确超时并移除重复限流等待。
2. 单一学术源失败会阻断整轮检索。本次加入OpenAlex候选发现路径，并把真实来源写入
   检索账本与方法段。
3. 中文模型会输出 `【P1】`、`[P1, P2]` 或裸 `P1`。现统一规范化为可解析的
   `[P1] [P2]`，同时正文引用统计不再被参考文献列表虚增。
4. 质量门只接受少数固定章节名，曾把标准“引言/结果/讨论/参考文献”误判为缺章。
   现改为语义章节组，并排除研究目的和方法记录造成的假阳性。
5. 独立审稿曾出现 `verdict=pass` 同时带有 `major_issues`。现规定只要存在重大问题或
   引用问题，最终状态强制为 `needs_revision`。
6. 试验运行器按DOI或arXiv ID优先去重，未合并同一论文的期刊版与预印本。Agent案例
   因此保留了P4/P5版本对。问题已如实记录；后续运行改为先按规范化完整标题去重。

## 使用边界

- 本轮是聚焦高负载验证，不是穷尽性系统综述。
- 候选发现使用OpenAlex，全文来自原始开放地址；未覆盖所有专业数据库和封闭出版物。
- 未执行双人独立筛选，也没有用人工金标准复核每一张证据卡。
- 源PDF在提取后删除；交付包只保留元数据、结构化证据和短候选摘要。
- API Key未写入代码、日志或产物。由于Key曾直接发送在对话中，试验完成后仍建议轮换。
